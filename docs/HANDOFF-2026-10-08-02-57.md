Prove the module hook end-to-end on the Pixel 8 test phone:
1. Get the Cloak companion app to publish its state to `/data/adb/cyclone_cloak/state-v1`.
2. Confirm the Zygisk module loads into a scoped app process.
3. See the `CloakModule: cloaking` log line when a bound app starts.

## 3. WHAT WORKS
- The companion app installs and launches.
- The Cyclone connector is authorized and shows `ready`.
- Identity import works.
- Binding creation works in the UI.
- Toggling bindings in the UI works.
- The app can invoke `su` (Magisk shows an allow policy for uid 10377).
- The module zip installs into Magisk and is visible in the module list.

## 4. WHAT DOES NOT WORK
1. The publish path is not completing.
   - `/data/adb/cyclone_cloak` exists, but `/data/adb/cyclone_cloak/state-v1` does not.
   - Therefore the module has no state to load.
2. The Zygisk module is not loading into the target app process.
   - `logcat` shows no `CloakModule` lines when Instagram starts.
   - `/proc/<pid>/maps` for Instagram shows no mapped `arm64-v8a.so` from the module.
3. The app UI may show bindings as `ready` internally while the publish step actually failed.
   - The internal bindings JSON says `state: "ready"` and `enabled: true`.
   - But the actual module state directory is missing, so the UI state is misleading.

## 5. SUSPECTED ROOT CAUSE
The publish step is likely being blocked by a mismatch between:
- the app's `su` call,
- the SELinux context used by that call,
- and the filesystem path it writes to.

Evidence:
- `su -c` from adb shell can read `/data/adb` but could not read or write `/data/adb/cyclone_cloak`.
- Using `su --context u:r:magisk:s0` sometimes reported `u:r:magisk:s0`, but file operations still failed with permission denied.
- We added Magisk SELinux policy rules to allow `magisk` to read/write `adb_data_file`, `system_data_file`, and `system_file`, but the publish path still did not complete.
- The module itself is enabled and its library is present, but because the publish path never lands, the module has nothing to load.
